## Modules

- **HeyGanesh.Abstractions** — shared Foundation project: PixelRect, GuidanceResult, GuidanceSource, GuidanceConfidence, GuidancePoint, MonitorInfo, MonitorCapture (moved from Intelligence/Platform during M1). Zero project references; consumed by Platform, Perception, Intelligence, Experience modules.
- **HeyGanesh.Providers.Core** — shared provider contracts: `ILlmClient`, `IEmbeddingClient`, capability model, `ProviderError`, `IProviderCatalog`, `IProviderRegistry`, resilience (timeout, bounded retry with jitter, per-provider circuit breaker). Zero NuGet; references Abstractions + Security. Assembly: `src/Providers/HeyGanesh.Providers.Core/`.
- **HeyGanesh.Providers.OpenAiCompat** — OpenAI-compatible HTTP adapter implementing `ILlmClient`. Covers OpenAI, Azure OpenAI, DeepSeek, Mistral, xAI, Groq, Together, OpenRouter, Ollama, LM Studio. Uses `System.Net.Http` (built-in). Assembly: `src/Providers/HeyGanesh.Providers.OpenAiCompat/`. References Providers.Core + Security.
- **HeyGanesh.Providers.Anthropic** — Anthropic Messages API adapter implementing `ILlmClient`. POST /v1/messages, x-api-key auth, anthropic-version header, system field, content blocks (text/image/tool_use/tool_result), SSE streaming, structured output via output_config. Assembly: `src/Providers/HeyGanesh.Providers.Anthropic/`. References Providers.Core + Security.
- **App Shell** — process host: owns DPI awareness, the service graph, and the hotkey → Voice → Context Orchestrator → Screen Overlay → Tutor Engine → spoken-answer wiring (DEC-012/DEC-014/DEC-016).
- **Context Orchestrator** — top-level state machine driving session lifecycle.
- **Screen Overlay** — per-monitor click-through overlay window.
- **Global Hotkey Monitor** — system-wide hotkey registration and dispatch.
- **Screen Capture** — frame acquisition via `Windows.Graphics.Capture`.
- **Element Selection** — PRIMARY coordinate-detection path (UIA enumeration + Jev choice); Vision is the fallback.
- **Vision / Coordinate Detection** — UI-element and coordinate detection (DeepSeek V4.1 Flash) — FALLBACK to Element Selection.
- **Jev** — classification / intent-routing engine; placement TBD, sits before the Tutor Engine call.
- **Tutor Engine** — academic/technical teaching layer: question (+ optional bounded, untrusted screen grounding and one capped visual) in, explanation text out; the only component allowed to answer the user; no screen actuation; provider seam fakes-verified + one live provider (DeepSeek `deepseek-flash`) behind `TutorClientFactory.CreateDeepSeek` (DEC-015/DEC-017).
- **Visual Lesson Engine** — `src/Intelligence/HeyGanesh.VisualLessonEngine/`: the VisualPlan v1 contract only (FEATURE-007 Phase 1, DEC-023) — parses model-authored lesson JSON (surfaces + beats of one spoken sentence and closed-set drawing ops), validates limits/vocabularies/reference integrity, and degrades bad beats to speech or the whole plan to text; `Runtime/` holds `LessonPlayer`, which plays a validated plan through the `ILessonCanvas` / `ILessonSpeaker` seams (draw then speak per beat, speech is the clock; pause/skip/stop). References Abstractions only; no rendering, speaking or provider calls. Lesson runtime, planner and renderer are later phases; the rendering stack waits on DEC-020.
- **Voice pipeline** — speech in/out seam: Qwen Gateway frontend → user transcript out, answer text in → Fish TTS (behind `ITtsClient`); never answers questions itself.
- **Notes persistence** — SQLite-backed notes store.
- **API key security proxy** — isolates LLM API keys from the rest of the application.

## Module details

### App Shell (implemented)
- **Assembly:** `src/Experience/HeyGanesh.App/`, `net8.0-windows10.0.22621.0`, zero NuGet (project-refs GlobalHotkeyMonitor + Voice + ContextOrchestrator + ScreenOverlay; ScreenCapture/ElementSelection/Vision arrive transitively and are used directly). See [DEC-012](./DECISIONS.md#dec-012--2026-09-29--pixel-canary) and [DEC-014](./DECISIONS.md#dec-014--2026-09-30--cline-agent-model-id-not-exposed-to-the-agent).
- **Public surface:** an entry point and flags, not a library — `--once` (one turn at startup, hook never installed: with `--question` the legacy text path, without it one live listen), `--question` (LEGACY/verification only; ignored with a warning in hooked mode, where the microphone is the question source), `--seconds`, `--cancel-ms`, `--duration-ms`, `--no-overlay`, `--foreground`, `--no-retain-captures`, `--no-speak`, `--max-dim`, `--max-candidates`, `--no-dpi`, `--help`. Exit codes: 0 verdict produced (an honest no-match counts, and so does a silent or release-abandoned voice turn) / 1 verdict failed **or no transcript was produced** / 2 shell could not start / 3 provider error propagated / 4 unexpected fault / 12 required key missing / 13 cancelled — the post-verdict teach/speak leg reuses exactly these codes (DEC-016).
- **Pipeline:** `Program` sets process-wide PerMonitorV2 awareness, then composes one `ScreenCaptureService`, `ElementSelectionService`, `VisionService`, `ContextOrchestratorService` and `ScreenOverlayService` (the overlay borrowing the same capture service for monitor topology), one `GlobalHotkeyMonitor`, and one `VoiceService` (its constructor opens no devices — the microphone is taken per listen). A **turn** is: `Pressed` → `TriggerPump.OnPressed` starts `VoiceService.ListenOnceAsync` on the pool; `Released` → `OnReleased` ends the utterance; a committed `FinalText` becomes `options.Question` and flows through the one unchanged `HandleHotkeyPressedAsync` → `ShowAsync` → reported `OverlayShowResult` path. The hook callback and the monitor's worker thread are never blocked by a microphone, a Gateway socket, or a capture. A second trigger while a turn is in flight — or while its highlight is still on screen — is refused rather than queued, mirroring CO-10 and SO-8. A produced non-Failed verdict then runs the teaching leg (DEC-016): the shell alone maps it to a plain-data `TutorContext` (`Captures[0]` attached as a `DownscaledFrame` visual when Found, nothing when not), calls `TutorService.ExplainAsync` — and feeds the explanation verbatim to `SpeakAsync` unless `--no-speak`. Its `CreateTutorClient()` **still returns null** — the client exists since DEC-017 but the one-line flip is deliberately not taken, so the leg reports its honest skip and exits 0 until it is.
- **Voice turn outcomes (DEC-014):** a released-before-commit listen is abandoned cleanly (exit 0, nothing resolved — the Voice API has no force-commit call); `IsNoSpeech` is a verdict, not an error (exit 0, the orchestrator is never called, so silence costs no capture); a `Failed` utterance is exit 1 (no transcript, no fabricated verdict); shutdown during a listen is exit 13. `VoiceService.SpeakAsync` is now called — by the teaching leg after a produced verdict, reading the Tutor's explanation verbatim (DEC-016); while the shell's `CreateTutorClient()` still returns null (the flip pending after DEC-017) the leg reports its skip, so in practice the speaker still stays silent.
- **Lifecycle:** shutdown is ordered and load-bearing — release the hook, cancel the lifetime token, wait (bounded, 5 s) for the turn in flight, then let reverse-declaration disposal run: hotkey → voice → overlay → orchestrator → legs → capture. Awaiting the turn before the overlay and the Voice service are disposed is what stops a turn completing into a disposed listener. Ctrl+C is a clean exit (0) and reports hook health; a turn interrupted by shutdown is reported, not propagated as the process's code.
- **Boundary:** it owns process-global state and nothing else. No confidence threshold, no fallback rule, no display policy — a verdict is reported and drawn exactly as the orchestrator normalized it (DEC-009/DEC-010/DEC-011 all keep those decisions out of the host). It renders no window of its own: the overlay is the UI. No input injection of any kind, and no test doubles — fakes stay in verification hosts, so the shell carries no `--fake` flags. It never answers a question: Voice supplies the transcript, the orchestrator decides, the overlay draws, the Tutor answers and the speaker reads — the shell maps and wires, deciding nothing itself, and DEC-016 keeps even the mapping data-only.

### Context Orchestrator (implemented)
- **Assembly:** `src/Intelligence/HeyGanesh.ContextOrchestrator/`, `net8.0-windows10.0.22621.0`, zero NuGet (project-refs ScreenCapture + ElementSelection + Vision; deliberately no reference to GlobalHotkeyMonitor). See [DEC-010](./DECISIONS.md#dec-010--2026-09-23--cline-agent-claude-sonnet-45).
- **Public surface:** `ContextOrchestratorService.ResolveAsync(question, ct)` → `GuidanceResult`, plus `HandleHotkeyPressedAsync(question, ct)` — the trigger receive point the host wires `GlobalHotkeyMonitor.Pressed` to — and `Phase` / `IsSessionActive` / `Options`; `ContextOrchestratorOptions` (`Target`, `RetainCaptures`); the normalized verdict types `GuidanceResult` / `GuidanceSource` / `GuidanceConfidence` / `GuidancePoint`.
- **Pipeline:** one session = one capture (`CaptureAllMonitorsAsync`, cursor's display first) → PRIMARY leg `ElementSelectionService.SelectAsync` → only if that result is Failed, the FALLBACK leg `VisionService.LocateAsync` on the cursor's frame, once → the leg's verdict normalized into `GuidanceResult`. Phases: `Idle → Capturing → Selecting → [VisionFallback] → Resolved`. Overlapping sessions are refused, never queued; all awaits share one token linked to the caller's and to `Dispose`.
- **Normalization boundary:** this is the only assembly that sees both result types. `SelectionResult`/`VisionResult` and their duplicated `ConfidenceLevel` stay untouched; the mapping is total and lossless (Found, description, box/center in global physical px, tier, every raw signal) and gates nothing — no threshold, no re-scoring, no invented fallback rule (DEC-009's deferral, executed here, without a shared abstraction assembly).
- **Boundary:** guide-only — it resolves coordinates for the next module and never injects input, renders, or captures anything beyond the one frame per session. It does not own DPI awareness, hook lifecycle, or the question source (the question arrives as a `UtteranceResult` from Voice and is already committed when it gets there), so key/HTTP failures and cancellation propagate to the caller unchanged.

### Screen Overlay (implemented)
- **Assembly:** `src/Platform/HeyGanesh.ScreenOverlay/`, `net8.0-windows10.0.22621.0`, zero NuGet (project-refs ScreenCapture + ContextOrchestrator). See [DEC-011](./DECISIONS.md#dec-011--2026-09-24--muse-spark).
- **Public surface:** `ScreenOverlayService.ShowAsync(GuidanceResult, ct)` → `OverlayShowResult` (`Displayed`, `Reason`, `ShownFor`, `WindowCount`), plus `HideAsync`, `IsShowing`, `VisibleDuration`, `Dispose`; `ScreenOverlayOptions` (bounded `VisibleDuration`, `ShowBox`/`ShowPointer`, `RequirePerMonitorDpi`, `BoxThickness`/`PointerRadius`).
- **Pipeline:** verdict checks (`Failed` before `Found` — the CO-6 asymmetry) → one borderless `WS_POPUP` layered window per monitor the box touches (global-to-local is a translation, never a scaling) → `CaptureExclusion.TryExcludeFromCapture` on every real top-level HWND (hard gate) → show without activating → remove on duration, `HideAsync`, cancellation or disposal. `Found=false`/failure/off-screen renders nothing; one show at a time (second call refused, never queued).
- **Input contract:** windows carry `WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_NOACTIVATE | WS_EX_TOPMOST | WS_EX_TOOLWINDOW`, return `HTTRANSPARENT` from `WM_NCHITTEST` (`WS_EX_TRANSPARENT` alone is insufficient for a top-level window) and `MA_NOACTIVATE` from `WM_MOUSEACTIVATE`. No `SendInput`, no `SetCursorPos`/`SetFocus`/`SetForegroundWindow`, no injection, no UIA writes exist anywhere in the assembly — the first visual act of the tutor answers, the user always acts (CONSTRAINTS.md, DEC-011).

### Screen Capture (implemented)
- **Assembly:** `src/Platform/HeyGanesh.ScreenCapture/`, `net8.0-windows10.0.22621.0`, zero NuGet.
- **Public surface:** `ScreenCaptureService` (`EnumerateMonitors`, `GetCursorMonitor`, `IsCaptureSupported`, `CaptureMonitorAsync`, `CaptureAllMonitorsAsync`, `Dispose`); `CaptureExclusion` (`TryExcludeFromCapture`, `TryIncludeInCapture`); `ScreenCaptureOptions` / `MonitorCapture`. See [DEC-004](./DECISIONS.md#dec-004--2026-09-21--glm-53-flash).
- **Boundary:** owns everything from HMONITOR to a JPEG `byte[]`. It does not render, does not move the cursor, does not touch the clipboard, and returns nothing for Vision to interpret. DPI awareness is deliberately the host's decision.

### Element Selection (implemented — the PRIMARY coordinate-detection path)
- **Assembly:** `src/Perception/HeyGanesh.ElementSelection/`, `net8.0-windows10.0.22621.0`, zero NuGet (project-ref to ScreenCapture only).
- **Public surface:** `ElementSelectionService.SelectAsync(string question, SelectionTarget? target = null, CancellationToken ct = default)` → `SelectionResult`. **The entry point is `SelectAsync`, not `LocateAsync`** — `LocateAsync` is Vision's; the two modules are siblings, not one API. `SelectionTarget`: `CursorWindow` (default — where the user is looking) / `ForegroundWindow`. `IJevClient` is the transport seam (`TypeSafeJevClient` today; bearer key read from `TYPESAFE_API_KEY` at call time, reported as presence/length only); `SelectionOptions` (`MaxCandidates` 120, `ModelId` `jev-1.13.0`, `BaseUrl` `api.typesafe.ai`, `IncludeNoneOption` true, `PerCallTimeout` 30 s). `CandidateEnumerator.Enumerate` → `CandidateSet`; `CandidateRanker.RankAndCap`; `UiaCandidate` / `TargetWindowInfo`. See [DEC-008](./DECISIONS.md#dec-008--2026-09-22--cline-agent-model-id-not-exposed-to-the-agent) and [DEC-009](./DECISIONS.md#dec-009--2026-09-22--cline-agent-model-id-not-exposed-to-the-agent).
- **Pipeline:** UIA enumeration of the target window (`Enumerate` — one cross-process cache-request pass over the control view) → interactive filter (nameless / offscreen / disabled dropped, and Text/Pane/Group/Custom excluded because dense text is Vision's job) → `RankAndCap` by lexical overlap with the question, capped at 120 and re-idded `c001..` → Jev answers the "choice" question over that manifest plus the synthetic `none` escape → the chosen candidate's **UIA `BoundingRectangle` is the coordinate answer**. Jev only ever selects among offered ids: it cannot emit coordinates or free text, and a choice id that was never offered is refused rather than mapped (hallucination guard).
- **Confidence:** `blended = 0.5 * JevConfidence + 0.5 * WinnerProbability`, tiered `>= 0.8` High / `>= 0.5` Medium / else Low (`ElementSelectionService.Mapping.cs`) — deliberately the same 0.8/0.5 boundaries as Vision so a consumer can compare the two paths. Threshold-free by contract: the raw signals (`JevConfidence`, `WinnerProbability`, `NoneProbability`, `PlausibleProbability`, the per-option distribution) are surfaced, never gated here.
- **Composition:** Element Selection is the **PRIMARY** path; **Vision is the FALLBACK**, invoked only on a failed result (`FailureReason != null`: no resolvable window, empty interactive tree, UIA access denied by UIPI, Jev returned no choice, or an unmapped choice id). `SelectionResult` mirrors `VisionResult`'s shape (Found, Description, `BoxOnScreen`/`CenterOnScreen` in global physical pixels, three-tier `Confidence`) but the two modules **must not reference each other** — `ConfidenceLevel` is intentionally duplicated, and unification is deferred to the Context Orchestrator (DEC-009).
- **Boundary:** guide-only — it resolves a rectangle and never injects input; the `SetFocus` slot in `UiaInterop.Interfaces.cs` exists for COM vtable alignment only and is never called. Geometry reuses `PixelRect` in global physical screen pixels; DPI awareness stays the host's decision. No capturing, no rendering. The direct `TYPESAFE_API_KEY` path is temporary, mirroring DEC-007.

### Vision / Coordinate Detection (implemented — FALLBACK to Element Selection)
- **Assembly:** `src/Perception/HeyGanesh.Vision/`, `net8.0-windows10.0.22621.0`, zero NuGet (project-ref to ScreenCapture only).
- **Public surface:** `VisionService.LocateAsync(MonitorCapture, question)` → `VisionResult` (`Found`, description, normalized/image/source/screen boxes, `Confidence` + `RawConfidence`/`Consistency`, per-sample diagnostics); `IVisionClient` seam; `VisionOptions`. See [DEC-006](./DECISIONS.md#dec-006--2026-09-22--laguna-s-21) and [DEC-007](./DECISIONS.md#dec-007--2026-09-22--laguna-s-21).
- **Boundary:** consumes one `MonitorCapture` per call (no capturing, no multi-monitor fan-out); screen-space boxes reuse `PixelRect`, the same physical-px contract as `MonitorInfo.Bounds`. No rendering, no clicking, no proxy deployment — the direct-key path is temporary pending the API key security proxy module.

### Screen Overlay (contract inherited)
- Before drawing anything, call `CaptureExclusion.TryExcludeFromCapture(hwnd)` on the real top-level HWND so the capture module cannot photograph its own output. Affinity is per window and must be re-applied on every window recreation.

### Voice pipeline (implemented — wired into the shell as the question source; DEC-013/DEC-014)
- **Assembly:** `src/Experience/HeyGanesh.Voice/`, `net8.0-windows10.0.22621.0`, zero `PackageReference`, **no project-refs at all** (not to ElementSelection, Vision, ContextOrchestrator or ScreenOverlay — Voice turns audio into text and text into audio and knows nothing about coordinates, guidance verdicts or overlays). See [DEC-013](./DECISIONS.md#dec-013--2026-09-30--cline-agent-model-id-not-exposed-to-the-agent).
- **Public surface:** `VoiceService.ListenOnceAsync(ct)` → `UtteranceResult` (`FinalText` | `IsNoSpeech` | `FailureReason`+`Failed`); `VoiceService.SpeakAsync(SpeakRequest)` → `SpeakResult`; seams `IVoiceListener`, `ITtsClient`, `IAudioOutput`, `IMicrophoneSource`; implementations `QwenGatewayClient`, `FishTtsClient`, `WinMmAudioOutput`, `WinMmMicrophoneSource`; pure protocol layer `QwenGatewayProtocol` + `GatewaySuppressionLedger`.
- **Pipeline (in):** winmm capture (16 kHz mono PCM16) → `input_audio_buffer.append` over the qwen-audio-agent Gateway Client Protocol (wire 7.0, `session.hello` → `session.ready`) → `transcript.final role=user` is the ONLY text ever returned; `response.started` triggers `response.cancel`+`interrupt`, all `audio.delta` is dropped, all `role=assistant` transcripts are dropped and counted (`GatewaySuppressionLedger`), `task.*` aborts the listen (Backend Agent must be off, `AGENT_PROTOCOL=none`). Transport is per-utterance. See [FLOW.md](./FLOW.md).
- **Pipeline (out):** `SpeakRequest` → `FishTtsClient` (`POST /v1/tts`, `format=wav`, `sample_rate=44100`, transport-streamed response body) → `WavPcmReader` (validates RIFF/PCM16/mono, fails loud) → `WinMmAudioOutput` (`waveOut*`, cancellation is a real stop via `waveOutReset`).
- **Boundary:** it answers nothing — no intent classification, no question routing, no computer actions (the P/Invoke surface moves audio only). Keys stay in env at call time (`FISH_AUDIO_API_KEY`, DEC-007 pattern); the Gateway's provider key never crosses the protocol; results and logs carry presence/length only. Silence (`IsNoSpeech`) is a verdict distinct from provider/network/auth failure (`Failed`), mirroring the `Choice=="none"` vs failed-selection rule. Both external runtimes (Gateway, Fish) are replaceable by swapping the injected seam — they are services, never dependencies.


### Tutor Engine (implemented — the answer layer, consumed by the shell's teaching leg; first live provider built, shell flip pending)
- **Assembly:** `src/Intelligence/HeyGanesh.TutorEngine/`, `net8.0-windows10.0.22621.0`, zero NuGet and **zero ProjectReference** (not ContextOrchestrator — the input is a plain-data `TutorContext` snapshot; not ScreenCapture — the visual is opaque caller-cropped JPEG bytes; not Voice — siblings stay siblings, DEC-008/DEC-009 discipline applied to the teacher). See [DEC-015](./DECISIONS.md#dec-015--2026-09-30--cline-agent-pixel-canary).
- **Public surface:** `TutorService.ExplainAsync(TutorRequest, ct)` → `TutorResult` (`ExplanationText` ≤1600 chars, token accounting, `ModelId`, `Latency`); seam `ITutorClient` (`CompleteAsync(TutorPrompt, ct)`, disposable, caller-owned — the service holds no `IDisposable` because it owns nothing); data types `TutorRequest/TutorContext/TutorVisual/TutorPrompt/TutorCompletion/TutorResult`; `TutorOptions` (500 output tokens, 400-char untrusted-description clamp, 512 KiB/1568 px visual caps); exception family mirroring Voice's (12/3 exit mapping), no shared-abstraction assembly.
- **Boundary:** `TutorService` owns the system prompt and renders every prompt deterministically (TU-10); all screen-derived text enters labelled `UNTRUSTED DATA`, visuals cross as separate capped bytes never base64-spliced into text, coordinates are metadata banned from answer prose. No capturing, no decoding, no windows, no audio, no input — the assembly's P/Invoke surface is empty because there is none (TU-8). Verification is `tools/TutorSmoke` (TU-1..TU-11 offline; TU-12 live-gated). The first live provider exists since DEC-017 (DEC-015's neutrality ended by owner decision, not by drift): `DeepSeekTutorClient` (internal — model `deepseek-flash`, direct Chat Completions, `DEEPSEEK_API_KEY` read at call time per DEC-007, fixed `thinking:{"type":"disabled"}` for spoken-answer latency/budget) constructed only via `TutorClientFactory.CreateDeepSeek(...) → ITutorClient`. The shell's `CreateTutorClient()` still returns null (DEC-016) — the flip to the factory call is a one-line change, deliberately not yet taken; until then the leg prints its skip after every verdict and returns exit 0.
