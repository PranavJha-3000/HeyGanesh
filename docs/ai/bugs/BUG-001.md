# BUG-001 — session.ready's version was read from the wrong field, so the wire-version check never ran

- **Date found:** 2026-10-30 · claude-opus-5-5 (while building the loopback Gateway stub for VO-11, DEC-040)
- **Found by:** claude-opus-5-5
- **Severity:** major (a safety check that silently did nothing against a real Gateway)
- **Status:** verified
- **Module(s):** Voice Pipeline (`QwenGatewayProtocol.Classify`, used by `QwenGatewayClient`'s handshake)

## Replication
1. Have a Gateway answer `session.hello` with upstream's ready shape:
   `{"type":"session.ready","protocol_version":"8.0.0",...}` (field name from `GatewaySessionReadySchema` in
   qwen-audio-agent `shared/protocol/gateway-client-protocol.mjs`, main branch, checked 2026-10-30).
2. Listen with `QwenGatewayClient`.

## Expected vs actual
- **Expected:** a major-version mismatch refuses the listen ("negotiated wire version '8.0.0' ... refusing").
- **Actual:** the classifier looked only for `protocolVersion` and `protocol`, found neither, recorded the version as
  "not stated by session.ready", and listened normally. Against a real 7.0 Gateway the check was skipped every time.

## Root cause
The classifier's comment said the ready payload's schema "was not fully verifiable at write time", so the field name
was guessed in camelCase. Upstream uses snake_case `protocol_version`. The offline row VO-6 tested the guessed name, so
it passed; nothing ran against the real shape.

## Fix
- `src/Experience/HeyGanesh.Voice/QwenGatewayProtocol.Classify.cs` — read `protocol_version` first; the two older
  spellings stay as fallbacks.
- `tools/VoiceSmoke/VoiceSmoke.Asserts.cs` — VO-6 classifies an upstream-shaped ready frame.
- `tools/VoiceSmoke/GatewayStub.cs`, `VoiceSmoke.Preroll.cs` — the stub sends `protocol_version`; VO-11 adds a
  major-8 Gateway that must be refused with no audio sent.

Also checked against upstream while here (`gateway-events.mjs`): transcripts carry `role` and `content`, and
`input_audio_buffer.append` carries `audio`, which match the client.

## Verification
- `VoiceSmoke --assert-gcp-events` -> 21 PASS (new: upstream-shaped ready, version 7.0.0), exit 0
- `VoiceSmoke --assert-preroll` -> 13 PASS (new: protocol_version 8.0.0 refused, no frames sent; recorded version 8.0.0), exit 0
- With the old field name restored on purpose: VO-6's new check fails ("not stated"), and VO-11's major-8 Gateway is
  listened to (2 checks fail). Restored; both rows pass again.
