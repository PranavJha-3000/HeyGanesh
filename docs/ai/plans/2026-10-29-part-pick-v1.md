- Picking prefers solid parts over see-through ones: the first real-click run found the connecting rod unclickable behind the

- The test click is one `SendInput` (move + down + up) and its points must be steady 2 px around: 2 of 3 runs with a separate

## Problem, restated

Step 4 draws Part Library models in a scene window, but the window is look-only and closes when the
turn ends (`LessonTurn` disposes its lease in `finally`). FEATURE-007 §2.4 promises: "surface emits
`part-clicked(partId)`; session turns it into a follow-up question bound to that part". So the student
should be able to click the connecting rod once the engine lesson has played and get a short follow-up
lesson about the connecting rod, in the same window, without speaking.

The App Shell can't reach this until step 6 (the planner doesn't produce 3D ops yet and the shell
passes no catalogue). Like step 4, step 5 is exercised by its verification hosts only; the shell is
not touched.

## Decisions proposed (owner to confirm)

1. **Picking is on only after the lesson has finished playing.** A click mid-lesson does nothing. The
   page shows "Click a part to ask about it" once picking is on.
2. **The follow-up reuses the same window.** No second 2 s cold start: the canvas is reset and the
   follow-up lesson plays in it.
3. **The question is written by C#, from the catalogue**, never from page text: e.g. "Tell me more
   about the connecting rod in the four-stroke engine." The page sends only two ids (instance, part);
   the host checks both against what it actually drew and against the catalogue, and drops anything
   else. The previous plan goes along as `PlanRequest.PreviousPlan` (the existing DEC-022 follow-up
   path, already pinned by LP `--assert-followup`).
4. **Bounded:** at most 3 follow-ups per lesson; the window closes after 60 s with no click, on the
   close button, or on cancel.

## Execution path (FLOW.md)

Documented today: `LessonTurn.RunAsync` → `VisualPlanner.PlanAsync` → `ILessonCanvasHost.OpenAsync` →
`LessonPlayer.PlayAsync` → dispose. New, documented in FLOW by this change:

```
RunWithFollowUpsAsync
  turn 1 = plan → open lease → play
  loop (≤ MaxFollowUps):
    canvas is IPartPicker and plan drew a scene?  no → stop
    EnablePickingAsync(true) → WaitForPickAsync(idle)
      page click → scene.pick → post part-clicked(ids) → CardWindow.PartClicked
      → CardSurface validates ids vs drawn instances + catalogue → completes the wait
    null (closed / idle) → stop
    question = PartQuestion.For(pick, catalogue); PreviousPlan = last plan
    plan → (Rejected/provider error → stop, report it) → ResetAsync + play on the SAME lease
  dispose lease (every path)
```

## Alternatives considered

- **Picking during playback (click interrupts the lesson).** Rejected for v1: it races the speaker,
  needs a stop-then-replan path the player doesn't have, and the demo works fine after the lesson.
  Easy to add later as "Stop, then pick".
- **A new window per follow-up (keep `RunAsync` as the only path).** Rejected: 2 s of blank window
  every click, and the old model vanishes before the new lesson is ready.
- **Let the page send the part's name and use it as the question.** Rejected: page text would become
  model input; ids checked against the catalogue keep the question C#-authored.
- **Put the follow-up loop in the App Shell.** Rejected: the shell carries no fakes (DEC-012), so the
  loop couldn't be tested offline; LessonSession is where the turn already lives.

## What could break, and how we'd know

- **A click is misread as a drag or vice versa.** Drag is only on the title tab today; the canvas has
  no camera controls attached. `--assert-pick` clicks the real canvas and checks no drag happened
  (window position unchanged).
- **Picking the wrong part** (pick hits an inner mesh or a label). Labels are GUI, not meshes; the walk
  goes up to the part node. `--assert-pick` checks the exact part id for a known screen point.
- **The idle wait keeps a window open forever / leaks.** Bounded by the idle timeout and cancel;
  LT row checks the lease is disposed once on every path.
- **Existing behaviour changes.** `RunAsync` untouched; existing LT, LSU and LS rows rerun unchanged.
- **High-DPI click offsets.** The projected centre is converted to physical pixels with the window's
  DPI; if it is wrong the `--assert-pick` row fails rather than passing on luck. Only verified at this
  laptop's scale (I'll state the scale in the report).
