## Problem, restated

Every turn is gone when it ends. The question, the verdict, the Tutor's answer and the lesson that was drawn and
spoken live only in memory and, since the tray (DEC-052), as lines in a log file. So a student cannot look back at
or replay a lesson they were taught, and nothing could use earlier turns as context.

AGENTS.md and PLATFORM.md have listed "SQLite notes" as planned since the start, for review and session context.
BUILD-PLAYBOOK left one decision open, D3: reach SQLite through Windows' own `winsqlite3.dll` (no NuGet) or through
the `Microsoft.Data.Sqlite` package. Windows' copy is on this PC (`C:\Windows\System32\winsqlite3.dll`, SQLite
3.53.4); it ships with Windows 10 and 11.

## Design

**New module `src/Foundation/HeyGanesh.Notes`.**
- It uses `winsqlite3.dll` through P/Invoke, as BUILD-PLAYBOOK D3 recommends: zero NuGet, like the core modules.
- It references nothing; plans are stored as JSON text, so it never needs the lesson engine.

**The store:** `%LOCALAPPDATA%/HeyGanesh/notes.db`, or `$HEYGANESH_DATA_DIR/notes.db`.
- Each turn becomes one row:
  - when it happened, and the session it belongs to;
  - the transcribed question;
  - the leg that ran (highlight, Tutor or lesson) and the route;
  - the verdict in words: source, found, the element's description, confidence;
  - the Tutor's answer text, or the validated lesson plan's JSON and title;
  - the follow-up parts clicked;
  - the outcome.
- **Never stored:** screenshots, screen text, keys.
- **Mechanics:**
  - WAL journaling and a busy timeout, so the tray and the console exe can both write;
  - the schema version kept in `PRAGMA user_version`, with migrations in code;
  - a database that will not open is moved aside as `notes.db.broken-<stamp>`, and a fresh one starts, with a
    log line (nothing is lost silently).
- **Retention:** the newest 1,000 turns are kept. That is a guess; your call (below).

## Execution path

New, not yet in FLOW.md (12b adds it):

```
TeachAsync → (leg ran, verdict produced) → TurnNote.From(question, route, verdict, tutor text | lesson plan, picks, outcome)
  → NotesStore.Record(note)
```

A failure to write is logged and never fails the turn. Replay in 12c:

```
NotesStore.Get(id) → VisualPlanParser + Validator → LessonPlayer on CardSurface
```

## Alternatives considered

- **`Microsoft.Data.Sqlite` (NuGet).** It is the friendlier API, but it is a new dependency, and Windows already has
  SQLite. It stays the fallback if `winsqlite3` fails verification on a supported Windows version.
- **JSON-lines files per session (no SQL).** These are the simplest to write. But delete-one, retention, listing
  across sessions, and two processes writing at once all get hand-rolled. Rejected, but a workable fallback.
- **ESENT** (Windows' built-in database engine). No dependency either, but a much heavier API for this job.
- **Storing screenshots for review.** Rejected: large, and they hold whatever was on screen, including other apps.

## What could break, and how we'd know

- **`winsqlite3` exports or version differ on an older Windows build.** NS-1 checks `sqlite3_libversion` and the
  exports at start; the store reports "unavailable" and the shell runs without notes, never crashing.
- **Two processes writing.** NS-4 runs two writers at once.
- **The shell gets slower.** The note is written after the turn, on the pool; SH rows time the turn end.
- **Privacy.** The database keeps questions and answers in plain text in your profile folder, like the log does
  (you chose to keep transcribed questions). "Clear all" in 12c, and uninstall says the data folder is kept.
