## Problem, restated

The Tutor is built and tested offline. `TutorService`, its prompt rules and the DeepSeek client behind
`TutorClientFactory.CreateDeepSeek` all exist (DEC-015/DEC-017). But the shell never uses it:
`ShellHost.CreateTutorClient()` returns `null` on purpose, so every turn that should be explained in prose prints
"tutor : skipped — the teaching seam is wired but has no client yet". That covers:
- a plain question without `--lesson`;
- any turn the router (DEC-036) sends to "explain".

DEC-017 left the switch as a one-line change for you to decide, and you chose it as must-have 2.

There's one complication, found while building 8b. **TU-8**, a deliberate DEC-017 check, refuses any
`DeepSeekTutorOptions` property whose name contains "Key", "Secret", "Credential" or "Handler". That's so the Tutor's
options can never hold a credential or a transport hook. So the Tutor can't take the key ring's reader the way the
other clients now do. It would read only `DEEPSEEK_API_KEY`, and a key stored with `--set-key` (which is how the tray
app, step 11, will store keys) would never reach it.

## Your decision: TU-8

| Option | What changes | Result |
|---|---|---|
| **A (recommended)** | TU-8 allows exactly one exception: `ApiKey` of type `Func<string?>`. It's a source the client calls per request, never a value, and the same shape as `SelectionOptions`, `VisionOptions` and `FishTtsOptions` (DEC-046). Any string or byte field named Key/Secret/Credential, and any handler, is still refused. | The Tutor reads through the key ring like every other client. The rule's purpose holds: no credential can be *stored* in the options, and there is still no transport hook. |
| B | TU-8 unchanged; the Tutor stays environment-only. | Works only with `DEEPSEEK_API_KEY` set. A student who stores the key through the app gets lessons but no prose answers. |
| C | The App copies the stored key into its own process environment at startup. | Rejected. Every child process inherits the environment, including the WebView2 card windows, so the key would spread further. |

## Design (option A)

- **TutorEngine** (same pattern as 8b):
  - `DeepSeekTutorOptions` gains `Func<string?>? ApiKey`. Null keeps the `DEEPSEEK_API_KEY` read, so TU-11 and every
    host behave as before.
  - `DeepSeekTutorClient` calls it per request.
  - A source that returns nothing is a missing key: `TutorAuthenticationException`, and no request is sent.
- **App Shell:**
  - `CreateTutorClient()` returns `TutorClientFactory.CreateDeepSeek(new DeepSeekTutorOptions { ApiKey = Keys.Reader("deepseek") })`
    when `HasKey("deepseek")`, and `null` otherwise.
    - With no key, the turn still reports an honest skip (now "no DeepSeek key"), not exit 12. That matches how the
      lesson leg is gated (DEC-027).
    - The provider and model stay as DEC-017 committed them: DeepSeek `deepseek-flash`, the same key as the lesson
      planner.
  - The header's `tutor :` line says either "deepseek-flash, DEEPSEEK_API_KEY present (N chars, source)" or "off: no
    DeepSeek key", in step with `CreateTutorClient()`.
  - The skip text in `TeachAndSpeakAsync` names the missing key instead of DEC-015.
- **Unchanged:**
  - how a verdict becomes a `TutorRequest` (`MapGuidanceToContext`);
  - the speech leg and the exit-code mapping;
  - the router.

  The "explain" route now really explains.

## Execution path

```
verdict (not Failed)
```

A provider error after the verdict maps to 12, 3, 4 or 13, as SH-17 already specifies. The lesson leg and the
router are untouched.

## What could break, and how we'd know

- **Offline exit codes change.** With no keys, Element Selection still stops the turn at its key gate (exit 12)
  before any Tutor call, and with no DeepSeek key the Tutor is null and skips. Checked by: `--once --question "x"` →
  12, `--cancel-ms 60` → 13, `--once --lesson` → 12.
- **A Tutor call where there used to be a skip.** With a DeepSeek key, each explain turn now costs a DeepSeek call. I
  can't run this without your key (SH-17).
- **Missing speech key.** Without the Fish key, the spoken answer fails after the printed lesson with exit 12. That
  mapping already exists (SH-17); the printed lesson is still shown.
- **TU-8 loosened too far.** The amended check names the exact property and type. I'll prove it with a mutation: a
  string `ApiKey` makes TU-8 fail.

## Alternatives considered

- **Route "explain" turns to a 2D lesson instead of turning the Tutor on.** Rejected. A spoken prose answer is
  faster and cheaper for "what does this mean?" questions, and the video's tutor answers some questions in speech
  alone.
- **Turn the Tutor on, but environment-only (option B).** See the table above.
